# Деберц 2×2 — счётчик очков

## Что это за игра

«Деберц» — карточная игра на 4 игроков в двух командах (2×2), популярная
на Балканах, близкий родственник белота. В раздаче разыгрывается фиксированный
банк очков (обычно 162, плюс бонусы за белу/терц/полтинник), одна команда
объявляет игру в масть и должна набрать больше очков, чем соперник.

## Зачем это приложение

Один игрок за столом ведёт счёт со своего телефона вместо подсчёта на бумаге.
Вводятся только сырые данные раздачи (кто играл, сколько очков в банке,
сколько набрала одна из команд) — приложение само считает очки обеих команд,
включая нестандартные исходы (БЗ, байт, висячий байт, см. ниже), и определяет
победителя при достижении цели (501 или 1001 очко).

## Стек

Next.js (App Router) + TypeScript + Tailwind CSS v4. Без бэкенда и БД — вся
игровая логика выполняется на клиенте. Счёт хранится в `sessionStorage`
(переживает обновление страницы, сбрасывается с закрытием вкладки — так и
задумано, счёт держится «в рамках сессии», а не постоянно).

Вся логика подсчёта — чистые функции в `src/lib/gameEngine.ts`
(`computeGame`, пересчитывает весь счёт с нуля по массиву `RoundInput` при
каждом изменении — это то, что делает undo последнего раунда тривиальным:
просто отрезать последний элемент массива и пересчитать).

Задеплоено на Vercel (проект `deberts-scorer`, привязан к GitHub-репозиторию
через Git-интеграцию — пуш в `main` деплоит автоматически, `vercel --prod`
нужен только для ручного форс-деплоя).

## Правила подсчёта (неочевидны из кода — сверено с игроком)

- **БЗ** (без взяток): если по введённым очкам у одной из команд выходит
  ровно 0 — это автоматический БЗ, не отдельный флажок в UI. Победитель
  получает банк раздачи **целиком**, у команды с БЗ **вычитается** штраф
  `bzPenalty` из её собственного счёта (не прибавляется к счёту соперника).
- **Байт**: играющая команда набрала строго меньше очков, чем соперник —
  весь банк уходит сопернику. Каждый 3-й байт одной команды (не обязательно
  подряд) — доп. штраф `threeByePenalty`, вычитается из её же счёта.
- **Висячий байт**: играющая и принимающая команды набрали ровно поровну.
  Доля принимающей команды выплачивается сразу, доля играющей — замораживается.
  Судьба заморозки решается **следующим же раундом**: если замороженная команда
  наберёт в нём больше сырых очков, чем соперник — заморозка прибавляется
  сверху; иначе (соперник набрал больше или снова ничья) — сгорает безвозвратно.
  Это НЕ «ждать следующей победы» — ровно один раунд lookahead, без
  бесконечного переноса.
